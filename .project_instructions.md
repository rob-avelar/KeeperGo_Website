## Dual Role System (May 2026)
- Users can have **multiple roles simultaneously** (ORGANIZER + GOALKEEPER)
- `role` field = currently active role; `roles[]` field = all roles the user has
- Switch-role API only allows switching between roles already in `roles[]`
- New roles are added ONLY through signup/registration (merge flow)
- Dashboards only show "Switch to X Mode" button if user has both roles
- Dashboard pages check `roles[]` before allowing access; redirect to signup if role not found

## Forgot Password Flow
- Pages: `/auth/forgot-password` and `/auth/reset-password`
- APIs: `/api/auth/forgot-password` and `/api/auth/reset-password`
- Token-based (1h expiry), stored in `PasswordReset` model
- Email sent via NOTIF_ID_PASSWORD_RESET notification
- Links on all 3 signin pages (organizer, goalkeeper, generic)

## Admin Booking Alert
- On every new booking, email sent to `admin@keepergo.nl`
- Uses NOTIF_ID_NEW_BOOKING_ADMIN_ALERT
- Template in `lib/email.ts` → `sendNewBookingAdminAlert()`

## Notification IDs
- `NOTIF_ID_NEW_BOOKING_ADMIN_ALERT=ac95659d`
- `NOTIF_ID_PASSWORD_RESET=12500b627`

## Referral Credit System (May 2026)
- Referrer earns €5 credit (stored as 500 cents in User.referralCredit) after referred user's first completed booking
- Credit auto-applied as discount on referrer's next booking payment via create-payment route
- If credit covers full amount, booking confirmed without Stripe payment
- Goalkeeper always receives 75% of full totalAmount regardless of credit applied
- processReferralReward() in lib/referral.ts called from confirm, confirm-with-rating, auto-confirm-bookings routes
- Frontend: credit balance shown on referral card, discount breakdown on payment page
